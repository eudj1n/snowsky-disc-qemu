# Vosk RU TTS integration, 2026-09-21

Scope: optional third local TTS engine, five voices, existing normalization and
device-free listening comparison. No physical player command or firmware run.
The live 8090 configuration continues to select its existing Silero profile;
the new Vosk profile is an explicit alternative.

## Runtime and model provenance

- PyPI `vosk-tts==0.3.61`, `onnxruntime==1.23.2`, `numpy==2.2.6`,
  `tokenizers==0.21.4`, isolated Python 3.12 environment.
- `vosk-model-tts-ru-0.9-multi`, archive size 782787154 bytes; SHA-256:
  `0aa332451ce46bfdbd620e74765fc16a4087988067c299969121ed0f8ed5bdf2`.
  All seven extracted file digests are pinned in `voice/vosk_model.py`, including
  dictionary, configuration, BERT model/tokenizer and both model cards.
- Model configuration declares `multistream_v1`, five speakers (`female_0..2`
  mapping to IDs 0..2, `male_0..1` mapping to IDs 3..4), 22050 Hz mono output.
- The model and bundled BERT README declare Apache 2.0. Upstream engine code is
  Apache 2.0; project adapter code remains MIT. External weights/audio are not tracked.
- Both ONNX sessions explicitly select CPU, sequential execution, two intra-op
  threads and one inter-op thread. The local loader supplies the pinned upstream
  `Synth` interface without invoking upstream auto-discovery/download.
- Shared `JsonWorker` owns one resident process per selected instance. Common
  runtime serialization, bounded messages/audio, cancellation/reaping, normalization
  and no-fallback behavior remain in effect. Result evidence identifies actual voice.

## Real failure retained

`Играет Linkin Park — Numb.` failed in upstream `Synth.g2p_multistream` with
`KeyError: 'u'`: the generated phoneme is absent from the reviewed model's map.
The adapter now reports this as an explicit unsupported-text synthesis error.
It neither removes the foreign name nor changes normalization/engine silently.
The common runtime closes resources after failure; a later explicit phrase can
start a new worker. Failures remain rows in the listening artifact.

The lightweight `ru_numbers` policy preserves Latin names by design. Optional
RUNorm can change their pronunciation but is not an automatic recovery mechanism
and has its own [observed errors](2026-09-21-silero-normalization.md).

## Checks and reproduction

Ten Vosk-specific tests cover all voice IDs, actual result identity, unsupported
locale/input, invalid WAV/rate, no retry on unsupported text, normalization without
changing the original response, file integrity, failed startup cleanup, safe archive
extraction and release of each comparison provider before loading the next.

The first real Vosk probe returned 22050 Hz PCM for `Пауза.`. The comparison uses
the same six synthetic phrases as the preceding Piper/Silero experiment. It now
finishes one provider's corpus and closes its runtime before loading another,
avoiding five simultaneously resident copies of Vosk's large model. This changes
the loading schedule; do not compare the two runs as a controlled benchmark.

```sh
python3.12 -m experiments.disc_assistant.assistant.voice.vosk_setup
experiments/disc_assistant/assistant/.venv/bin/python \
  -m experiments.disc_assistant.evaluation.tts_compare \
  --profile experiments/disc_assistant/assistant/voice/profiles/silero-ru-cpu.toml \
  --profile experiments/disc_assistant/assistant/voice/profiles/silero-runorm-ru.toml \
  --profile experiments/disc_assistant/assistant/voice/profiles/vosk-voices-ru.toml \
  --provider piper --provider silero_ru --provider silero_runorm \
  --provider vosk_0 --provider vosk_1 --provider vosk_2 --provider vosk_3 --provider vosk_4 \
  --output /tmp/disc-vosk-listening-new
```

Existing Piper service/voices and optional Silero/RUNorm installations must be
available when included in the matrix. Failed providers are recorded explicitly.
Local artifacts for this run live under `/tmp/disc-tts-vosk-listening-20260921/`.
They contain only synthetic text/audio, with per-call model/normalization/runtime
evidence. No listening-quality score, memory benchmark or ARM-board certification
is inferred. Current configuration guidance is in the [TTS guide](../guides/tts.md#optional-vosk-tts).
